# GitHub Actions Workflow Authoring

Conventions and gotchas for authoring `.github/workflows/*.yml` files in this monorepo.

## Rules

- **Errexit is ON before your `set` line runs** — GitHub Actions' default Linux shell is `bash --noprofile --norc -eo pipefail {0}`, so errexit (`-e`) is already active when your script starts. A `set -uo pipefail` line only adds nounset; it does NOT clear the inherited `-e`. If a workflow `run:` block intends manual/continue-on-error handling (e.g., accumulate failures across multiple checks and exit at the end), add an explicit `set +e` after `set -uo pipefail` to disable errexit. Without it, the first unguarded command failure will abort the whole step and skip remaining checks. (Note: Bash exempts a function body from errexit only when the function call is the left operand of `||`, e.g. `fn ... || FAILED=1`, so that specific pattern works even under `-e`, but explicit `set +e` is clearer for step-level error handling.)

- **Copy all validation steps when adding a new per-dependency section to `deps-bump.yml`** — The workflow validates externally-fetched version strings both for null/empty (basic guard) and for format (e.g., `grep -qE '^[0-9]+\.[0-9]+\.[0-9]+$'` before using in `sed`, git branch names, or version comparisons). When adding a new dependency section, copy the complete validation pattern from an existing section, including both null/empty checks AND format-validation regexes. Omitting format validation allows malformed upstream values to slip through, creating silent-merge hazards. During PR review, check that all validation steps are mirrored across new and existing sections.

- **Apply command-substitution error guards consistently across similar invocations** — In scripts that use `set +e` and explicit `|| { fail "..."; continue; }` guards to accumulate failures, if you guard the exit status of one command substitution (e.g., `var=$(yq '.foo' file) || { fail "..."; continue; }`), apply the same guard to all similar invocations in that script. Mixing checked and unchecked command substitutions is a silent-failure hazard: an unguarded `yq` parse failure produces an empty string, which is indistinguishable from a legitimate missing field, so the check appears to pass when it should have failed. Review checklist: for each `yq`/`jq`/similar command in a script, verify that either ALL invocations have explicit error guards, or NONE do (and the script is designed to tolerate failures gracefully).

- **When gating downstream jobs behind a fan-out job with `needs:` + `if:`, also add the fan-out job to branch-protection required-checks** — When using a pattern like `needs: changes` + `if: needs.changes.outputs.<group> == 'true'` (e.g., with `dorny/paths-filter`) to conditionally run jobs, GitHub Actions implicitly prepends `success()` to custom `if:` conditions. If the `changes` job itself fails (action bug, transient failure), all downstream jobs report "skipped" instead of running. GitHub branch protection counts "skipped" as "passing," so a failure in the fan-out job goes undetected — the PR merges without any verification. Fix: include the fan-out job's name (e.g., `watch-changes`) in the GitHub branch-protection required-status-checks list alongside the leaf-job names, so a fan-out failure blocks merge directly.

- **Bash scripts using `set +e` + `while read < file` must check readability, not just existence** — Accumulate-failures bash scripts that read a file via `while read < file` redirection must explicitly verify readability with `[ -r file ]` before entering the loop, in addition to checking existence with `[ -f file ]`. A failed input redirection (e.g., permission denied, ENOACCESS) silently fails to iterate without raising an error under `set +e`, so the loop body never runs and any failure-accumulator flag stays at its zero/success value. The script then falls through to print a "success" message and exit 0, a false-positive pass on a CI gate. Defense-in-depth: also add `|| fail "could not read $file"` after the loop's redirection (e.g., `done < "$file" || fail "could not read $file"`) to catch TOCTOU races.
