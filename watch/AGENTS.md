# Project: watch

Go backend (standard library).
GitHub Issues for tracking. GitHub for code and PRs.

## Critical Rules
- Narrow a match-miss exclusion to the exact case being excluded — never broaden it into a silent "no match → discard" catch-all; keep the original visible fallback for every other case and add a regression test for the non-matching case.
- When changing a literal value (exec flag, environment variable, version) referenced in comments, grep the whole file for all references to that literal rather than relying on a change plan's enumerated sites — doc comments and docstrings can reference the same value and go stale (#357).
- When adding a plugin package with a version-pinned manifest, register its path in `.github/workflows/watch-version-bump.yml`'s `plugin-json-paths` list — grep that file for the existing pattern. Unregistered manifests are never bumped and stay frozen at creation-time version (#488).
- Verify every caller of a precondition-dependent path uses the right constructor variant — `NewForLaunch` leaves `Engine.Runtime` unset for deferred re-resolution, `New` sets it eagerly, and `Engine.Launch` needs the former. A shared helper can hide a misclassified caller (#585).
- When adding subprocess calls in `internal/dispatch`/`internal/babysit`, mirror `mainsync.go`'s timeout/WaitDelay/stderr conventions, not bare `exec.Command`; use each package's own `execGh` helper (`gh.go`) for `gh` calls (#825, #852, #854).

## Project Structure

- `main.go` — CLI entry point: imports, version, `socket-dir`, top-level dispatch to each command group below, doctor/update wrapper-mode delegation; also handles the `cn` argv[0] alias (routes to `open`) and the `cenci-sand` argv[0] tombstone (prints a migration map, exits 2). All command-group implementations live in their own `*_cmd.go` file (same `package main`):
  - `daemon_cmd.go` — `daemon start|stop|restart|status` + PID-file management
  - `notify_cmd.go` — `notify` (hook event ingestion)
  - `run_cmd.go` — `run` (dispatch a workflow into a new tmux window)
  - `dispatch_cmd.go` — `dispatch` (enroll/unenroll/status/loop/plan-refined) + state rendering
  - `automerge_cmd.go` — `automerge on|off|status` (fleet-wide `automerge.enabled` toggle + informational repo policy summary)
  - `status_cmd.go` — human `status` + `widget-json` (hidden alias `waybar`) + render helpers
  - `close_cmd.go` — `close` + decision rendering; wires `windowproc.Killer` as `closecmd.Opts.KillProcesses`, each window bounded by `GraceFromEnv()` + `sandbox.CloseKillMargin`
  - `sandbox_cmd.go` — `sandbox build|build-base|prune|update-agent|update-plugins|reseed-creds|reap-orphans|ls|stop`: flag parsing, usage errors (exit 2), and dispatch into `internal/sandbox` + `internal/sandbox/launcher`
  - `open_cmd.go` — `open` (interactive sandbox launch, shortcut/model resolution)
  - `pipeline_cmd.go` — `pipeline` (six stage transitions: prepare/plan/await-input/execute/review/finalize) + `pipeline_mechanics_cmd.go` (label/worktree/worktree-cleanup/artifact), `pipeline_plan_cmd.go` (plan-check), `pipeline_reset_cmd.go` (reset)
  - `worktrees_cmd.go` — `worktrees ls|prune [--dry-run]` (#1266) for the repo containing the cwd: enumerates and classifies through `internal/worktreeclean`, with the in-use and babysit guards built from one `ReadLiveState` pass; `prune` re-reads the live state and re-runs both guards (strict) right before each `Remove`, and fails closed (`kept: in-use status unknown`) when tmux cannot be read, while `ls` and `--dry-run` still show the real verdict. Exit 1 on a runtime failure, a removal error or a half-done removal; 2 on usage errors

- `internal/daemon/` — Session-keyed event loop, hook→status mapping, paneless TTL sweep; delegates window work via `frontend.Frontend`. `windowcleanup.go` is the finished-ticket window-cleanup pass (#1251): loop snapshot of candidate windows → off-loop evaluate via `internal/ticketstate` → loop apply, which re-checks busy/babysit state right before each kill

- `internal/frontend/tmux/` — Interactive tmux frontend: window rename/style/restore, pane-based stale sweep, renumber migration, idle-title detection
- `internal/frontend/status/` — Read-only status JSON output (Waybar custom module protocol); consumed by `cenci status`, noctalia, and dms
- `internal/detect/` — Status enum, TaskName extraction, IsStatusSymbol
- `internal/tmux/` — tmux Client interface + ExecClient implementation, plus the launcher-facing `SetPaneOption` (pane user options through an explicit socket), the `ErrWindowGone` sentinel (`KillWindow`/`ListWindowPaneProcs` wrap it for a missing window or session), `ListWindowPaneProcs` (a window's panes with pid and launch options, reconciled against tmux's own pane_id/pane_pid pairs) and `ListLivePanes` (every pane's window name and current path from two listings joined on the pane id, one retry on a pane-set mismatch; the `ErrNoServer` sentinel, matched narrowly on `no server running`, is its only benign failure — every other error, a missing binary and a timeout included, must be read as "unreadable"). Imports no `internal/sandbox`

- `internal/pipeline/` — pipeline state machine and artifact storage: the `Stage` enum and `stageOrder` total order, flock-guarded transitions, `GetArtifacts`/`SetArtifacts`, worktree and label mechanics, plan-file discovery/validation, `Reset`, plan-file stage adoption (`adopt.go`: lets `plan --approve` succeed on a pre-stage-tracking ticket that has a valid `.plans/<id>-*.md` on disk), worktree attach/reuse (`AttachWorktree`: validates an existing worktree against `git worktree list --porcelain` and records it without creating anything), and the `.cenci/pipeline/<id>.json` format (its `session` map also carries the sandbox launch a `working` claim ran in, #1292: `SessionKeyLaunchID`/`SessionKeyContainer`/`SessionKeyRuntime`, written by `pipeline label --transition working`, removed by `ClearLaunch`, and validated by `ValidLaunchTriple`)

## Key Conventions

- **Interfaces**: `tmux.Client` defines the tmux boundary; `frontend.Frontend` is the seam the daemon injects at startup; implementations are swappable
- **Event-driven**: Daemon receives `HookEvent` from Claude Code hooks via Unix socket — no polling
- **Session-keyed state**: Daemon keys sessions by agent session id (fallback `pane:<id>` when only a pane is known); delegates all window work to the injected `frontend.Frontend`
- **Testing**: Behavior-driven tests across the frontend seam — the daemon suite wires a real tmux frontend over `tmuxtest.MockClient` and calls `handleEvent()`/`runSweep()` directly for synchronous, deterministic behavior; assertions target renames, window options, `WindowInfo`, and core session state (not internals)
- **Window state**: `windowState` in `internal/frontend/tmux` tracks per-window original name, original styles, original format strings, current status, pane ID, session ID, manual-name detection
- **User variables**: tmux frontend sets `@cenci-symbol` and `@cenci-style` per window for custom `status-format` integration; symbols are NOT embedded in window names. It also sets `@cenci-headroom-<agent>` (a global, session-wide option, not per-window) with each agent-type's remaining budget headroom as an integer percent. `cenci run` (not the tmux frontend) writes `@cenci-repo-dir` on every window it spawns — the absolute launch directory (`frontend.RepoDirOption`); a failure to set it only warns, and such a window is never auto-closed
- **Stale sweep**: Two mechanisms — the tmux frontend's `Sweep()` cleans up tmux-backed sessions whose pane no longer exists; the daemon's paneless TTL sweep expires sessions without a pane after `-session-ttl` (default `2h`). A pane-gone sweep pass and daemon startup each trigger one coalesced `cenci sandbox reap-orphans` self-exec (via the injectable `internal/reap.Reaper` seam) to kill orphaned container-side agent processes. The reaper's liveness is launch-ID keyed (#1252): `Engine.Launch` creates a 32-hex `CENCI_LAUNCH_ID`, records it (plus `@cenci-container`/`@cenci-runtime`) as pane options on `$TMUX_PANE` through the pane's own socket, and only then passes it in the exec env. A scanned process carrying an ID is live iff that ID is recorded on a live pane of its own socket (`list-panes -a -F '#{pane_id}<TAB>#{@cenci-launch-id}'`), so an orphan on a pane id reused after a tmux restart is reaped; the rule is strict (a live pane without that ID does not keep it alive), and the launcher alone writes the option (a manual `set -pu` of it on a live pane would make its agent reapable); the ID is written last, after `@cenci-container`/`@cenci-runtime`, so a partial tag failure never overwrites a previous live launch's ID, but two launches sharing one `$TMUX_PANE` still overwrite the pane's single `@cenci-launch-id`, making the earlier launch's processes reapable (one pane = one live launch is assumed). A process without an ID (started before this change, or launched outside tmux / with a failed tag) falls back to the (socket, pane) rule. Check order, all fail-open: malformed pane, container init, missing/malformed/unresolved socket, malformed launch ID (one aggregated `Note:`), launch-ID liveness, pane-ID fallback; a `list-panes` line with a non-pane first column or a non-empty invalid launch-ID column hard-fails the sweep before any kill. The in-container scan sanitizes the pane, socket and launch-ID fields to a fixed `__MALFORMED__` marker so a hostile environ value cannot forge or shift scan rows; `CountOrphanedSessions` counts launch-ID rows by (socket, launch ID) and legacy rows by (socket, pane).
- **Status recovery**: a hook event is the only way *into* `done`, so every state watch can be stranded in needs its own way out. `running` has two: the tmux idle-title ESC backstop (→ `stopped` after `titleStopQuiescence`) and the background-hold release (→ `done` after `frontend.BackgroundHoldTTL` of event silence, in both the tmux sweep and the daemon core's `backgroundHoldSweep` for paneless sessions). Anything that newly holds a session at a status must come with a bounded way out of it — an unbounded hold reads to users as "watch is stuck" (#1079).
- **Close-path kill** (#1253): `cenci close` and the daemon's pending-close kill a window's process tree before `kill-window` (`internal/windowproc.Killer`, shared by both). Order: TERM → poll for exit, capped at `CENCI_SANDBOX_REAP_GRACE_SECS` (default 5s, 0 = no poll) → KILL with the PID-reuse start-time check → for sandbox panes one bounded re-list (KILLs a late fork, reports survivors) → `kill-window`. Sandbox panes (launch ID, container and runtime all recorded) are killed by launch ID inside the container (`sandbox.KillLaunch`: `-u dev` probe, `-u root` signals); host panes by the process group of `pane_pid`, refusing pgid <=1 and the caller's own group (reported, never signaled; an ESRCH from `Getpgid` is re-probed via the group under that pid before the pane counts as gone). Limits, by design: a host kill reaches only the pgid of `pane_pid`, so a job-controlled interactive shell's foreground job (its own group) survives; a `setsid` process survives (the babysit supervisor); a process that scrubbed `CENCI_LAUNCH_ID` (`env -i`) is invisible to the launch-ID probe, and the reaper's (socket, pane) fallback sees it only if it kept `TMUX_PANE`/`CENCI_TMUX_SOCKET`. A failed kill never blocks `kill-window`: it is collected (`cenci close` exits non-zero) or logged (daemon), and a `kill-window` that reports the window gone (`tmux.ErrWindowGone`) counts as closed. Pane listing is reconciled against tmux's own `pane_id`/`pane_pid` pairs: forged or mismatched option rows are dropped and reported. Reported, not silent: processes whose environ the probe could not read (same user), and a partially tagged pane (container, no launch ID) whose in-container processes are not killed (the host group still is; the reaper covers the rest). Each window's kill is bounded at grace + `sandbox.CloseKillMargin` (60s) — `cenci close` per window, the daemon off the event loop through an async seam after deleting the registry entry on-loop; a goroutine dropped at daemon shutdown leaves the window open. The window-cleanup pass (#1251) uses the same seam but targets the tracked pane id `%N`, not `=session:index`, because the kill runs after the grace wait and an index can shift or be reused by then.
