# Go Gotchas

Standard-library and language traps in this codebase that pass review and tests but fail silently at runtime.

## Rules

- When returning a slice from a helper that can be empty (e.g., slice-building helpers in JSON-serialization code paths), initialize with `make([]T, 0)` rather than `var s []T` or leaving it nil — Go's `json.Marshal` serializes nil slices as `null`, not `[]`, breaking stable JSON contracts (e.g., `cenci audit --json` where the default-safe case has no boundary weakenings). Initialize with `make([]T, 0, cap)` to ensure empty results marshal as an empty array `[]`. Add regression tests asserting the absence of `:null` in JSON output and presence of `:[]` for empty cases (see `watch/internal/sandbox/launcher/audit_test.go`, lines 566–576, for the pattern) (#588).
- Functions that internally construct `bufio.Reader` over an `io.Reader` field (e.g., `bufio.NewReader(e.Stdin)` inside the function) are unsafe to call more than once against the same underlying reader — the second call's fresh reader has its own independent buffer and silently observes `EOF` even when bytes for it remain in the first call's discarded buffer, causing piped input (e.g., confirmation answers) to be silently lost. Either provide a `WithReader` variant that accepts a caller-owned reader (e.g., `PruneWithReader`), or ensure callers construct a single shared reader upfront and pass it to every invocation (#629).
- When building a regex or matcher pattern by splicing strings from a data-driven collection (e.g., `SupportedAgents`), guard against empty collections with an init-time panic (an empty slice silently degenerates to mismatches or over-match in deletion-critical paths like `sandbox prune`), and escape each element with `regexp.QuoteMeta` before joining (unescaped metacharacters in a future element would silently broaden the match instead of erroring). See `sandbox.go`'s `sandboxNamePattern`, `homeVolumePattern`, and `agentCLIVolumePattern` builders (#528).
- `os.IsNotExist`/`errors.Is(err, fs.ErrNotExist)` only classify filesystem-call errors — they never match an `os/exec` error. To handle a missing input file for an external command, `os.Stat` the path yourself first; don't infer it from the command's exit error.
- Closed-set enums must be audited as a group, in two directions. (1) Within one switch: when a new state/enum replaces a previously-collapsed failure mode (e.g. `CredentialProbePresent/Missing/Error` replacing "present or error → absent"), audit every branch including `default`/fallback for silently reproducing the original collapse — a default that maps unrecognized values to the "safest-looking" case defeats the point of distinguishing failure classes (#598). (2) Across functions: when adding a value to an enum already handled by multiple independent functions (e.g. `Posture.Dind.Source`, rendered by both `WriteText` and `WriteExplanation`), grep for every switch/branch over that enum and update them consistently — in #627 `WriteExplanation`'s dind switch missed the newly-added `DindSourceUnknown` case that `WriteText` handled, because the independent switches were not reviewed as a coordinated group (#627). Both risks are invisible to tests of normal cases: assert fallback rendering explicitly (e.g. `credentialStatusText`'s switch-default rendering distinct text per probe class), not just the absence of errors.
- Functions that return a single boolean to classify a git/command outcome must never collapse 'legitimate false answer' and 'command failed' into the same boolean value — the boolean alone cannot represent both. Example: an earlier version of `isAncestor(dir, ancestor, descendant) bool` returned `err == nil`, treating both `git merge-base --is-ancestor` exit code 1 (a normal, successful "not an ancestor" answer) and exit code ≥2 or context-deadline timeout (genuine command error) as the single `false` value, making it impossible to distinguish whether the ancestor check truly failed or whether git itself errored. Change to return `(bool, error)` — let callers distinguish legitimate-but-false (err=nil, bool=false) from genuine failure (err≠nil). This matters especially in gating/safety decisions where conflating failure classes silently breaks invariants (#822).
- `exec.CommandContext(ctx, ...)` + `CombinedOutput()` or `cmd.Output()` under a context timeout does NOT fully bound wall-clock time without also setting `cmd.WaitDelay`. When the context deadline expires, the direct child process is killed, but `cmd.Wait()` can still block indefinitely if a grandchild process (ssh, a credential helper, git-remote-https) inherited the stdout/stderr pipes and keeps them open. The timeout bounds only the command start time and execution duration, not its termination. Set `cmd.WaitDelay` on every `exec.Cmd` used with output-capturing functions under a context deadline to ensure the process fully terminates within the deadline (#822).
- When building glob/regex patterns for path matching (e.g., `matchesProtected` deny-list matchers), distinguish between anchoring for exact match vs. directory-prefix matching — a fully-anchored pattern (`^pattern$`) will not match directory prefixes with trailing slashes even if semantic intent was to match all paths under that directory. If config entries like `"watch/internal/sandbox/"` are meant to match as directory prefixes, the matcher must strip the trailing slash before building the pattern OR append a `.*` to treat the slash as a prefix marker: `"watch/internal/sandbox/"` → `^watch/internal/sandbox/.*$` or similar. Test directory-prefix patterns explicitly to verify they match both `"watch/internal/sandbox/file.go"` and nested subdirectories. Unanchored prefix matching silently renders security-relevant denylists inert — the config looks correct but matches nothing (#824).
