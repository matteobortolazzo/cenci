# Test Strategy Verification

Lessons on validating test assumptions during planning and ensuring direct coverage for unplanned implementation changes.

## Rules

- **Verify test strategy assumptions against actual code behavior before Q&A approval.** When a plan's approved test strategy depends on the control-flow or behavior of existing code outside the plan's declared file scope, examine that existing behavior and verify it actually supports the proposed observable. Don't assume or infer behavior from context; read the function. In ticket #122, the plan's Q&A approved a "log-buffer proxy" test strategy that required `CollectTickets` to attempt all configured repos even after one fails (to log newly-enrolled repos). The function actually had fail-fast behavior (return immediately on first repo error), making the test strategy unimplementable against unmodified code—a gap the planning phase didn't catch because `collect.go` wasn't in the declared plan scope. Planning scope and test strategy scope are distinct; if the test depends on a function's behavior, include that function in the verification process.

- **Write direct, dedicated tests immediately for unplanned code changes that support the plan's test strategy.** When implementation discovers that a file outside the plan's declared scope must be modified to make the approved test strategy work, write a direct unit test for that specific behavior change right away—don't rely on incidental coverage from integration tests or the original test suite. In ticket #122, the implementer changed `CollectTickets` from fail-fast to best-effort (attempt all repos, join errors) to unblock the approved reload tests. That change was only incidentally covered by the reload tests' log-substring assertions, not by a direct test of "CollectTickets attempts all repos and joins errors". The gap was caught during code review, requiring a follow-up delegation to add `collect_test.go`. Direct tests surface the behavior change explicitly and prevent reviewers from having to infer it.
