# tmux Behavior

Lessons on non-obvious tmux command behavior that differ from API expectations or vary by version.

## Rules

- **Unscoped tmux target resolution honors $TMUX_PANE environment variable.** Commands like `tmux display-message -p "#{session_name}"` (without `-t`) do not resolve to the server's most-recently-active session; tmux's cmd-find logic prioritizes any valid `$TMUX_PANE` from the client's environment ahead of most-recent-session, even ahead of a genuinely attached client on another session. This behavior is version-dependent (confirmed on tmux 3.4). When a test's red state depends on an external binary's resolution behavior, verify it empirically against the installed version before committing to the mechanics — do not assume unscoped forms ignore environment variables.

- **`tmux display-message -t <nonexistent-pane> -p "#{fmt}"` exits 0 with empty stdout instead of erroring.** Unlike most tmux subcommands (e.g., `rename-window`, `list-panes`), `display-message` with `-p` does not fail when the `-t` target is invalid; it succeeds silently with empty output. Production code must include an explicit empty-output check when a non-empty value is the contract — do not assume a tmux subcommand will error on an invalid target.

- **Status symbols belong in user variables, not window names.** Embedding a status symbol (▶, ✓, !, ~) directly in a window name breaks custom `status-format` configs: it doubles up with the config's own indicator inside `#W`, hardcoded colors override `window-status-style` changes, and users can't reference or control the symbol from their format strings. Set symbols via the `@cenci-symbol` user variable (per window) and style via `@cenci-style`; window names should contain only the task name or original name. For default-format users, prepend `#{@cenci-symbol}` to `window-status-format`/`window-status-current-format` during tracking and restore on cleanup.

- **`tmux has-session -t <name>` prefix-matches unless the target is exact-match-forced with a leading `=`.** `tmux has-session -t work` reports true against an unrelated session named `work-2` (and any other session whose name starts with `work`), because tmux's target-session resolution falls back to prefix matching when no exact name match exists. A probe that must confirm one specific named session exists — never a same-prefixed sibling — has to use the exact-match form `tmux has-session -t =<name>` (ticket #927, `internal/tmux.ExecClient.HasSession`). A nonzero exit (no such session, or no server running at all) is a normal "absent" result, not a command failure — callers should not treat it as noteworthy beyond the negative boolean.

- **Exact matching must continue after the session probe.** The grouped-session check and window creation carry the same leading equals marker used by the existence probe. The post-create window option exact-matches both the session and the independently parsed window name. Otherwise either target can disappear after the probe or creation and a bare target can resolve to a same-prefixed sibling. User-facing config, dry-run output, and errors keep the raw session name. Raw names that begin with an equals sign receive a separate exact-match marker. See ticket #937.

- **`tmux` transmits its client's full environment (and file descriptors) to the server during the `MSG_IDENTIFY_ENVIRON` handshake — use an allowlist when the socket target is attacker-controlled.** When `tmux -S <socket>` connects to a server, the client's entire environment is forwarded to that server; a hostile server can exfiltrate secrets (API keys, tokens, etc.). Do not scrub a denylist of known vars (e.g., TMUX, TMUX_PANE) from `os.Environ()` and forward the rest—this leaves secrets exposed. Instead, build the child env from scratch using an explicit allowlist (PATH, HOME, TERM, LANG only, populated only if set in the current process, via `os.LookupEnv`, never fabricated). The `CENCI_TMUX_SOCKET` is attacker-controlled—any container process can set it—so the reaper (through `tmux.RunSocket`, whose `minimalEnv()` in `internal/tmux/socket.go` is the one definition) constructs the allowlist env for tmux queries (#1007). Socket-path shape validation gates syntax errors but doesn't prevent dialing hostile sockets; the allowlist env is the exfiltration defense. The remaining socket hardening is tracked in #646, whose children #1428–#1433 replaced #1008; the allowlist behavior applies independently of them.

- **A tmux socket is hardened in four layers: shape, trusted directory, allowlist env, and a time bound (#1428, #1429).** (1) *Shape* — `tmux.ValidSocket` — an absolute path with no tab or newline, at most 1,001 characters; the daemon's ingest check additionally rejects any value that is not valid UTF-8 or contains a non-printable character (control, format) as `malformed`, so an ESC, CR, C1 control or bidi override can never reach the verbose logs. A failing `tmux.ValidSocket` value returns `tmux.ErrMalformedSocket` before anything is exec'd, never falling back to the ambient server. (2) *Trusted directory* — `tmux.CheckTrustedSocket`: the socket is exactly one name directly under `tmux.TrustedSocketDir()` = `EvalSymlinks(${TMUX_TMPDIR:-/tmp})/tmux-<uid>` (an unclean or nested path is rejected), and that directory must be a real directory (never a symlink), owned by the current uid, with no group or other permission bits. The directory is re-checked on every event at daemon ingest, so one swapped before the next event fails closed there; later tmux calls on a recorded socket rely on that check. Ingest also requires the path to exist as a Unix socket owned by the daemon's uid (`tmux.CheckSocketFile`, #1462; see the dead-socket bullet below). A rejected value means the default server, never an error to the user. The shape check runs first, because the directory check alone accepts a tab inside the final name. (3) *Allowlist env* — every socket-carrying call runs `tmux -S <socket>` with only `{PATH, HOME, TERM, LANG}` (see the allowlist rule above); an empty socket is bare `tmux` with today's argv and the ambient env. (4) *Bound* — a socket-carrying call is capped at 5s, plus a 2s wait for a grandchild holding the output pipes, and a timeout is reported as `context.DeadlineExceeded`; the bare empty-socket call stays unbounded as before. `$TMUX_TMPDIR` has to match between the daemon and the user's shell: a mismatch makes every hook-reported socket untrusted, and its windows fall back to the default server.

- **The daemon keys tmux state by (socket, target), never by the target or pane id alone (#1429).** `cenci notify` sends the first field of `$TMUX` as the hook event's `tmux_socket` (omitted when `$TMUX` is unset or that field is empty); the daemon validates it at ingest (see `hook-events.md`), stores it on the session next to the pane, and publishes it as `WindowState.socket`. `session:index` and `%N` repeat across tmux servers, so the tmux frontend's windows, panes and session mappings are keyed by `(socket, target)` and `(socket, pane)`, and the `pane:<id>` fallback session key becomes `pane:<id>@<socket>` for a non-empty socket (`frontend.SessionState.Key` and the daemon's `sessionKeyForEvent` must change together). Rename, style, restore and the repo-dir read run on the window's own server. A sweep tick lists panes once per distinct socket (sorted, `""` first), and a socket whose listing fails is left alone for that tick: a failed listing is never read as "pane gone" (a socket whose server is gone is handled by the dead-socket bullet below), while a pane gone from its own socket is swept even when the same id is live on another. `@cenci-headroom-<agent>` is set on the default server exactly as before and also on every non-empty socket hosting a tracked window; a socket first seen gets the last rendered values at once, one that no longer hosts a window is cleared on the next render, and shutdown clears them everywhere. An empty socket keeps today's calls, so a window tracked before an upgrade behaves unchanged. Every kill path targets the window's recorded socket (#1430): `cenci close` (`WindowState.socket` from the snapshot), the daemon's pending-close, the finished-ticket window cleanup and `windowproc`'s pane listing all pass the socket to both `list-panes` (`windowproc.Killer.KillWindowProcesses(ctx, socket, target)`) and `kill-window`, so a kill on one server never reaches a same-numbered `%N` on another. The pending-close registry is keyed by `(socket, pane)`; `ipc.PendingClose.socket` is the window's own recorded socket (never the caller's environment), checked at daemon ingest like a hook event's socket, and a rejected value is ingested as `""`. A registration only ever matches a window on the same socket, and an older `cenci close` client that sends no `socket` is keyed `("", %N)`, so it only matches a default-server window. An empty socket is the ambient server with unchanged bare-`tmux` calls. In the call log of the `windowproctest` fakes, a recorded socket leads each tmux call as `-S <socket>`; the fake tmux shifts it away after logging so its subcommand dispatch is unchanged.

- **A non-empty tmux socket whose server is gone stops being tracked, but only on evidence beyond a failed listing (#1462).** At ingest `Daemon.sanitizeTmuxSocket` also requires the trusted-directory socket path to exist as a Unix socket owned by the daemon's uid, checked with `Lstat` only and never by connecting (`tmux.CheckSocketFile`; a symlink is rejected because `Lstat` does not follow it); a missing path, a non-socket or a foreign owner is rejected as `untrusted` and the event falls back to the default server, so a forged path with no server behind it never joins the sweep. In `Sweep`, a non-empty socket whose listing failed on this tick is declared dead by one of two rules. (a) *Socket file gone*: `tmux.CheckTrustedSocket` still passes for `tmux.TrustedSocketDir()` and `Lstat` of the path reports "does not exist" (`tmux.SocketGone`); any other `Lstat` error, or an untrusted directory, is unknown and is left to rule (b). (b) *Long-unreachable and silent*: the listing has failed on every tick for at least `-session-ttl` (the streak starts at the first failed tick and any successful listing resets it) and every session on the socket has been silent for at least `-session-ttl`; `-session-ttl 0` disables only this rule, rule (a) still applies. For a dead socket every window on it is discarded without restore and without any tmux call (`@cenci-headroom-*` variables on it are dropped, not cleared), every pane-backed session on it gets a `Remove` sweep action without `PaneGone` so no reap pass is triggered, and the socket leaves the listing set so the next tick makes no `list-panes` call to it. A later event naming the same path goes through ingest again and starts fresh. The empty socket (the default server) is excluded from both rules and keeps its calls and failure behavior unchanged. The streak lives in memory only.

- **The launch side names one explicit socket end to end, and a rejected socket never reaches the ambient server (#1431).** (1) *Resolver and gate/spawn identity* — `cenci run` targets `--tmux-socket` when given (shape-checked: a bad value is exit 2 before any tmux call; an explicit socket that is not `$TMUX`'s first field with no `--session` is also exit 2, because `$TMUX_PANE` only means something on its own server), else `tmux.ResolveSocket()` (the first field of `$TMUX`, else `<trusted dir>/cenci`). Every `Controller` call in `run.Run` goes to that one socket, never `""`, so a headless or outside-tmux run and `cenci dispatch` use the `cenci` socket rather than the default server. `applyDispatch` resolves the socket once per real pass (a dry run resolves none) and hands the same string to the `HasSession` gate and to `run.Opts.TmuxSocket`, so the gate and the spawn cannot diverge; a resolver error makes every probed repo `session probe failed` and nothing is probed on the ambient server. (2) *Babysit `launchSocket`* — arming records the socket beside `launchSession`: the `--tmux-socket` flag, else the first field of `$TMUX` for a session resolved from the arming pane (the server that bare lookup actually queried; inlined because `internal/babysit` cannot import `internal/run`), else empty for an explicit `--session` (nothing says which server holds it). The deferred launch, the `ci-repair`/`merge-repair` liveness probes and a re-arm after `babysit reset` all use it, and the `cenci run` it starts gets `--tmux-socket` only when one is recorded. A state file without `launchSocket` keeps probing `has-session` with bare `tmux` (legacy). (3) *Fail closed on re-check* — babysit's `execTmux(socket, ...)` re-checks a non-empty socket (`ValidSocket`, then `CheckTrustedSocket(TrustedSocketDir())`) on every call and errors without exec'ing on a failure; the launch then fails, `cenci run` is never called and no attempt is spent. It never falls back to bare `tmux`. `defaultTmuxHasSession` checks `context.DeadlineExceeded` before `*exec.ExitError`, because `RunSocket` joins a timeout onto an exit error and a timeout must be a probe failure, not "session absent". (4) *Allowlist env whenever a socket is set* — the detached supervisor inherits the daemon's full environment, so a non-empty socket goes through `tmux.RunSocket` (`-S`, `{PATH, HOME, TERM, LANG}` only, 5s bound) and an empty one stays today's bare call. (5) *Arm path* — `ipc.ArmRequest.TmuxSocket` (`tmux_socket`, omitted when empty) comes from the sandbox launcher's `CENCI_TMUX_SOCKET` and is validated on receipt by `Daemon.sanitizeTmuxSocket`; a rejected value becomes `""`, is logged only under verbose without echoing a malformed value, and is not a nack. `armSessionForPane(ctx, socket, pane)` resolves `%N` on that socket through `tmux.RunSocket` inside `armSpawnBudget` (an empty socket keeps the bare call), and the supervisor argv gets `--tmux-socket <socket>` only when set, so an empty socket keeps today's argv. *Accepted risk*: nothing proves that an arm request's pane/socket pair belongs to the container that sent it. *Residual mismatch*: with an empty socket and `$TMUX` unset (a legacy state, or an explicit `--session` with no socket) the babysit probe asks the default server while `cenci run` launches on the `cenci` socket, so a session that exists only on the default server fails visibly at launch, and a same-named session on both servers would not be caught. A `tmux -S <custom>` host setup whose socket is outside the trusted directory fails closed at launch for the same reason: the re-check refuses it rather than dialing it.

- **Pane user options need `set-option -p` (tmux 3.0+), and an unset `#{@opt}` expands to the empty string in `-F`.** The launcher records `@cenci-launch-id`/`@cenci-container`/`@cenci-runtime` on `$TMUX_PANE` with `tmux -S <socket> set-option -p -t <pane> -- <key> <value>` (`tmux.SetPaneOption`); on tmux older than 3.0 the set fails and the launch falls back to legacy (socket, pane) liveness with a warning. The reaper reads the option back with `list-panes -a -F '#{pane_id}<TAB>#{@cenci-launch-id}'`: a pane that never had the option prints `<pane>` and a trailing TAB with nothing after it (not an error, not a missing column), so parse with a split on the first TAB and treat an empty second field as "no launch ID". A line whose first column is not a pane id, or whose second column is non-empty but not a valid launch ID, is a hard error, not a "no ID" pane: the sweep aborts before any kill and the dispatch capacity gate fails closed. The launcher's tagging call goes to its own trusted `$TMUX` socket with an explicit `-S`/`-t` and a timeout, never through the ambient pane resolution (#1252).

- **Always pass an explicit `-S <path>` rather than relying on ambient `$TMUX`/`$TMUX_PANE` ownership resolution.** `cenci sandbox reap-orphans` is self-exec'd by the daemon (`internal/reap`), a process whose own `$TMUX`/`$TMUX_PANE` may be unset entirely or may point at a server unrelated to the containers' panes it's classifying — the first "unscoped tmux target resolution honors `$TMUX_PANE`" rule above means an unscoped query would silently resolve against the *reaper's* ambient pane instead of the socket a container actually reported, misclassifying liveness. The reaper resolves each referenced socket's live panes (and recorded launch IDs) with an explicit `-S <socket>` per query, never bare `tmux` (#1007, #1252).

- **Don't `strings.TrimSpace` tab-delimited `tmux -F` output, in parsers or tests — trim only the trailing `\n`.** A `list-panes -F '#{pane_id}<TAB>#{@opt}'` line for a pane with the option unset ends in a bare TAB, and `TrimSpace` strips that TAB, collapsing the row's shape so the second column disappears. A test built this way passes locally only when tmux is absent (it skips) and breaks on machines that have tmux. Use `strings.TrimRight(out, "\n")` and then split on the first TAB (#1252).

- **`kill-window` and `list-panes` on a vanished target fail with "can't find window" / "can't find session" / "can't find pane"; classify only those as `tmux.ErrWindowGone`.** A window that closed itself between the snapshot and the kill is "already closed", not a failure, so `windowCmd` wraps `ErrWindowGone` when stderr contains any of those messages and the close paths count it as closed. A pane-id target (`%N`) whose pane is gone reports "can't find pane", so it is a missing target too. Deferred or async kills (anything that runs after the grace wait) should target a pane id (`%N`): an `=session:index` target is resolved again at kill time, and indices shift under `renumber-windows` and are reused by new windows. Keep the match that narrow: no-server ("no server running", "error connecting to"), protocol/version errors and timeouts stay plain errors, so a real tmux problem is never read as "already closed". The exact missing-target text is unverified against a real tmux (tmux was not installed where #1253 was built); confirm it on a machine that has tmux if the wording ever matters (#1253).

- **User pane options are printed raw by `list-panes -F`, so a newline or tab inside one can forge extra well-formed rows.** `@cenci-launch-id`/`@cenci-container`/`@cenci-runtime` are writable by any container process through the tmux socket; a value containing `\n` plus a fake `%9\t4242\t...` yields a row with an attacker-chosen `pane_pid`, and a five-field row check alone accepts it. List the fields tmux itself owns separately (`list-panes -F '#{pane_id}\t#{pane_pid}'`: no option can reach them) and accept an option row only when its `(pane_id, pane_pid)` matches one of those pairs exactly, with the pane id appearing once in each listing; drop and report every other row (`tmux.ListWindowPaneProcs`, #1253).

- **A "who is alive" read that gates an irreversible action joins two tmux-owned listings on `pane_id`, and only `no server running` is benign.** `tmux.ListLivePanes` (#1266) runs `list-panes -a` twice (`#{pane_id}<TAB>#{window_name}` and `#{pane_id}<TAB>#{pane_current_path}`) and joins them on the pane id, retrying once when the two pane sets differ; a duplicate or non-`%<digits>` pane id, a still-mismatched set, an empty or non-absolute path, a missing binary, a timeout and every other tmux error are "unreadable", and the caller (`worktreeclean.InUseGuard`) keeps the worktree. Only stderr containing `no server running` maps to `tmux.ErrNoServer` ("nothing is running"); `error connecting to` stays a plain error. That wording is unverified against a real tmux, so confirm it on a machine that has tmux. The read targets the ambient server only, so panes on another socket are invisible to it.
